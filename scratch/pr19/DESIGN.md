# PR-19 설계 제안

원본 프로토콜의 연구 근거와 측정 정의는 변경하지 않는다. PR-12의 기록 UX를 재사용하되 PR-19 데이터와 완료 상태는 분리한다.

## 프로세스
`DAILY_OVERVIEW → DAY_ENTRY → EDITING → DAY_COMPLETED → WEEK_OVERVIEW`. 화면에는 다음 고정 문구를 사용한다.

> 오늘 어떤 좋은 일이 있었나요? 그 일이 왜 좋았는지도 함께 적어 보세요.

하루에 최대 3개의 입력을 제공한다. 각 입력은 좋은 일과 그 이유를 하나의 자유 텍스트 값으로 작성한다. 앞뒤 공백을 제거한 뒤 내용이 남아 있는 입력만 유효한 것으로 판단한다. 유효한 입력이 최소 1개 이상이면 사용자가 제출할 수 있으며, 제출 시 결과를 저장한다.

제출 시각(`submitted_at`)의 사용자 로컬 날짜를 `entry_date`로 생성한다. 권장 5분은 내부 기록용이며 화면에 진행률·남은 시간을 표시하지 않고 완료 조건으로 사용하지 않는다. 저장 후에도 수정·삭제할 수 있으며 날짜별 과거 기록과 주간 요약을 조회한다. 7일 전체 수행 여부와 일일 완료는 별도로 관리한다.

## 확정/제안
- 확인 사실: 원본 duration·eligibility·constraints·연구 근거.
- 확정된 제안: 고정 입력 문구, 단일 content 데이터, 최대 3개·최소 1개 유효 입력, 공백-only 제외, 제출 타임스탬프 기반 날짜, 숨김 내부 시간.
- 제안: 브라우저 날짜/시간대, 과거 날짜 편집, 주간 개요, localStorage 내보내기·삭제.
- 검토 필요: 하루 중복 입력 정책, 날짜 변경 기준, E11/E12 연구 결과의 해석. 효과를 보장하는 문구는 사용하지 않는다.
